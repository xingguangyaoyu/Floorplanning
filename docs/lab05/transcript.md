## 12. 托住 D 的是哪一段？

key: lift-anatomy / 章节4 / 视图lift-anatomy / 文字推导

当前播放文字：把 D 的查询区间画出来：它覆盖 x 从0到3，这一段里有两段轮廓——C 的顶部2和B的顶部3。取最大，D 落在3。“右孩子坐在父块上”只是标准树里的巧合，不是算法。只看父块顶边的程序，在这里会写错。

画面短句：查询[0,3)：C顶2、B顶3，取最大3；不是父块顶边的2

## 13. 查询是整段区间，不是单点

key: segments / 章节5 / 视图segments / 文字推导

当前播放文字：轮廓查询有两个要点：一是覆盖整个 [x,x+w)，宽块要跨过好几段；二是只看有正长度的重叠，边界相接不算。只查一个点或只查父块，都会漏掉别处的高的段。

画面短句：B 查询 [3,5)：区间里哪怕一段很高也托得动

## 14. 残段：被切开后剩下的尾巴

key: residual-detail / 章节5 / 视图residual-detail / 文字推导

当前播放文字：看这棵树：D 先占 [3,6) 高1；C 作为 D 的右孩子落在 x=3、宽2，只盖住 [3,5)，把 [5,6) 留成高1的残段。后来 B 的查询区间 [5,7) 里最高的就是这段残段，所以 B 落在 y=1。如果程序把 [3,6) 整段删掉重写，残段丢失，B 会落到 y=0，和 D 重叠。

画面短句：D占[3,6)；C只盖[3,5)，残段[5,6)=1托住了B

## 15. 两类编辑，两种影响

key: neighborhoods / 章节6 / 视图neighborhood-cards / 文字推导
